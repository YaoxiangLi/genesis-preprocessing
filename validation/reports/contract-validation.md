# Reference, cell and pseudobulk contract validation

The schemas under design/ are JSON syntax within valid YAML 1.2, validated with jsonschema 4.26.0 from the existing MultiQC 1.35 image (no new system installation). The reference-registry prototype verifies actual fixture bytes, including compressed/decompressed FASTA identity and chromosome-size hashes; it rejects missing identity, malformed checksums, ambiguous canonical IDs, changed FASTA content and damaged sizes. Annotation/masking/provider/organellar fields are explicit; this is not a general reference acquisition service.

Pseudobulk tests were written first and recorded a missing-implementation failure. The implemented standalone fixture rejects unknown barcodes, duplicate cell records, duplicate unique-fragment rows, invalid intervals, unspecified biological replicate identity, invalid reference hashes and inclusion of absent modalities. Explicit technical merging is supported only within identical biological/reference/coordinate identity. Independent libraries remain separate. Input ordering does not affect output.

The actual synthetic pseudobulk FASTA is fixtures/pseudobulk/reference.fa (one 1,000-base chr1); its computed SHA256 is embedded in both library records. The reference-registry fixture is a separate 12-base reference and is not substituted for this genome. The six expected groups total nine unique fragments, while support sums to twelve. Model cut conversion tests cover raw, +4/-5 and +4/-4 inputs without silently double shifting.

Multiome tests retain five metadata rows, include three ATAC fragments under the explicit toy policy, preserve original annotations and prove RNA inclusion changes do not affect ATAC fragments. No universal doublet or plant threshold is enforced.

Exact commands/time/exit/output are in results/incremental-prs/{registry-content-final,metadata-schema-identity-final,pseudobulk-identity-final,multiome-identity-final}/. Outputs are in results/contracts/. The initial metadata schema test correctly rejected the fixture's wrong `thresholds` field; the fixture was corrected to the required `qc_thresholds` field, not the schema weakened. The reference and pseudobulk prototypes remain outside production ingestion. BGZF exporters, actual barcode correction/cell calling and model training are not claimed by these tests.

The separate processing-provenance schema requires code, registry checksum, immutable container identity, parameters, timestamp, task versions and original source identifiers. A contract-validation event explicitly has no Nextflow/sample sheet; a Nextflow-run record must supply both. Positive and missing-field tests pass in processing-provenance-schema evidence. This schema is a prototype contract, not a claim that every existing output already conforms.
