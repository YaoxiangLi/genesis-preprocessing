# Model-ready sc/snATAC pseudobulk contract, version 1

Status: executable synthetic contract, separate from production. Tests were written and failed on the missing implementation before `fixtures/pseudobulk/contract.py` was added. No real data have been connected. Plant QC thresholds remain **UNSPECIFIED**.

Identity hierarchy is study → biological sample → biological replicate → library → library-scoped cell/nucleus barcode → versioned annotation → pseudobulk task. A sequencing accession does not identify a biological replicate. Missing replicate identity blocks model-ready export. Species, exact assembly and FASTA checksum, accession/cultivar/ecotype, tissue, developmental stage, treatment, condition, assay, protocol and biological replicate are explicit task dimensions. Annotation checksum is independently nullable, never implicitly taken from another release.

Technical libraries remain separate unless an explicit technical_merge_group is supplied. A merge group must have identical biological identity, reference and coordinate convention. Different biological replicates always remain separate. Pseudobulks are formed per cell type per replicate first; any later pooling is a separate derived artifact with a parent-task list and an explicit purpose. No replicate pooling is performed by this prototype. Same coordinates in different cells remain independent molecules. Duplicate rows for the same library/barcode/coordinates are rejected rather than silently collapsed.

Canonical intermediate: sorted BED0, half-open fragments.tsv.gz, BGZF plus tabix BED index. Required columns are chromosome, start, end, barcode, positive integer read-pair support. Optional producer columns (including strand) are declared in metadata and preserved by adapters. Count one unique fragment per row for depth and model cut sites; support records observed multiplicity and must not multiply signal by default. Library identity accompanies each source file; pseudobulk export must retain a reversible library/barcode mapping, not concatenate ambiguous barcodes. The toy implementation emits inspectable JSON groups rather than claiming to be a production BGZF exporter.

Coordinate semantics are mandatory metadata: producer, producer version, offsets already applied, interval convention, contig dictionary checksum and deduplication scope. Keep producer coordinates at ingestion; do not silently re-shift them. The 10x documentation describes +4/-5 shifts and support including duplicates; the inspected ENCODE_scatac converter uses +4/-4. These are not interchangeable metadata. Each model adapter declares its target convention and tests endpoints. [10x fragment specification](https://www.10xgenomics.com/support/software/cell-ranger-atac/latest/analysis/outputs/fragments-file).

Every cell retains author_original_label, harmonized_label, ontology_id when available, annotation_source, annotation_status/confidence, cell-calling and doublet status. Labels are versioned data, not filename guesses. QC metrics include fragments, unique fragments, duplicate fraction, TSS enrichment, peak overlap/FRiP, mitochondrial/plastid fractions and low-MAPQ fraction, with null meaning unavailable. Metrics and inclusion decisions are separate. Thresholds are UNSPECIFIED; fractions must lie in [0,1] as a mathematical constraint, not a biological acceptance rule. An included modality must be present.

Task identity is `genesis-task-v1-` plus SHA256 of canonical sorted JSON biological identity, reference/annotation checksums, coordinate convention, library/explicit technical-merge scope and harmonized cell type. The full identity object travels with the task. A human label is optional; it is never the key. Each task includes source-cell records, input checksums, selection/annotation policy versions, source accessions, tool/container identities, Genesis SHA, exact parameters, timestamp and output checksums. Changing labels or inclusion policy requires a new content/provenance version even if biological task identity remains stable.

Required model-facing bundle: fragments and source-cell membership, usable unique-fragment count, reference identity, cut-site representation with exact offsets and count units, metadata and QC JSON. Unnormalized cut-site bigWig, peaks and training-region/split manifests are required by the chosen model adapter, not automatically interchangeable with DAP-seq RPKM tracks. Peak caller/mode, pooled-peak lineage and background selection must be recorded. No library-size normalization, duplicate removal or cell filtering is inferred at export.

## Downstream code inspection

ChromBPNet was inspected read-only at local commit `ece97c93ccaa2d9ee5bc5687e62f4dbf8d055367`. Its preprocessing accepts BAM, fragments or tagAlign, FASTA/chromosome sizes, ATAC/DNASE designation, narrowPeak-format regions and background regions; training uses chromosome-fold JSON and a bias model. Default sequence/output windows are 2114/1000 bp; include context/jitter margins in split design and prevent overlap/leakage. Plant chromosome splits and compatible bias training must be explicit; human defaults/pretrained biases are not justified for plants.

In `helpers/preprocessing/auto_shift_detect.py`, fragment-to-tagAlign emits two ends per row and ignores support. `reads_to_bigwig.py` interprets supplied plus/minus shifts as offsets already present, then converts ATAC intervals to +4/-4 before `genomecov -5`. A source interval [10,30) with +4/-5 offsets yields model cut positions 10 and 30; raw offsets 0/0 yield 14 and 25; +4/-4 yields 10 and 29. These exact known answers are tested. Supply declared offsets to avoid ambiguous shift inference and double shifting. Cut counts are base-resolution, unnormalized counts; controls/bias models are not DAP-seq treatment controls.

Cherimoya is pinned at `8ecf7f791ec07c05a701076cc58a0f845bf97609` in benchmarks/cherimoya. `cherimoya/io.py` and pipeline/config code establish 2114-bp input, 1000-bp output defaults, optional controls, and explicit signal grouping. Flat bigWig lists are separate unstranded channels; nested plus/minus pairs have reverse-complement channel semantics. Default human chromosome splits must be replaced. Pipeline conversion offsets default to zero; explicit precomputed signals and loci avoid silently inheriting conversion or MACS3 settings. Cherimoya controls are optional and are not the same requirement as ChromBPNet's factor/bias workflow. Training, model accuracy and plant bias calibration were not tested here.

## Known-answer fixture and acceptance

Two biological samples/replicates, L1 and L2, share barcode strings AAA/BBB/CCC. An extra L1 barcode DDD contributes to cell type A. Expected unique fragments: r1 A=3, B=1, C=1; r2 A=1, B=2, C=1; total 9. Read-pair support sums to 12 but does not change these counts. Tests cover permutation invariance, duplicate metadata/rows, unknown barcodes, negative coordinates, absent included ATAC, explicit technical merging and cross-replicate rejection. Results: `results/contracts/pseudobulk.json`; command/resource evidence: `results/incremental-prs/pseudobulk-{red,green}/`. BGZF/index export and model training remain future integration work, not silently claimed by these contract tests.
